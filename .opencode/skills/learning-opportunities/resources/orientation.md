# Repo Orientation: Landscape Designer

> Generated by orient. Re-run to update.

## One-line purpose

A React web app where a user uploads a property photo, then places Florida-native and edible plant species from a built-in catalog at true-to-scale size on an interactive canvas, and exports the resulting design.

## Primary language(s)

- **TypeScript** (dominant; strict), with **JavaScript (ESM)** for the Node-side data/build scripts (`db/seed.mjs`, `scripts/generate-art.mjs`) and a touch of **SQL** (canonical schema in `db/schema.sql`).

## Pipeline / workflow stages

1. **`npm run data` (offline build step)** — `db/seed.mjs` validates `db/seed/species.json` against `src/data/vocabulary.json`, writes `src/data/generated/plants.json`, and (on Node >= 22) sanity-checks `schema.sql`; `scripts/generate-art.mjs` deterministically emits SVG placeholders to `public/plants/`.
2. **App shell** — `src/main.tsx` mounts `src/app/App.tsx`, which code-splits the three feature views (Projects, Catalog, Designer) with `React.lazy`.
3. **Catalog read** — any feature calls `usePlantCatalog()` → `getPlantRepository()` (JSON snapshot) → typed `Plant[]` + `plantsById` map.
4. **Project lifecycle** — user uploads a photo → `compressImageFile()` downscales to a JPEG data URL → `createNewProject()` → `saveProject()` (localStorage index + document) → `openProject()` seeds the designer store.
5. **Design session** — `designerStore` holds the scene; `EditorCanvas` renders the photo + placements and routes pointer events through a gesture state machine (select/move/scale/rotate, pan, calibrate) into store actions; `DesignerView` subscribes and autosaves via `persistActiveProject()` → `saveProject()`.

## Key files

- `src/app/App.tsx` — shell + lazy feature views. Read first to see the layering rule (app composes features) and code-splitting.
- `src/core/domain/design.ts` — the feet-based world-coordinate model, `pixelsPerFoot()`, `placementSizeFeet()`. Defines all designer geometry, so it's the most decision-dense file.
- `src/features/designer/designerStore.ts` — the zustand design session and its snapshot undo/redo model. The heart of the editor.
- `src/features/designer/EditorCanvas.tsx` — the SVG canvas: gesture state machine, screen↔feet conversion, selection/scaling/rotation handles, calibration line. Most complex interaction logic.
- `src/features/catalog/usePlantCatalog.ts` — the single call site that resolves the `PlantRepository` implementation; the backend/mobile swap point.
- `src/core/repositories/jsonPlantRepository.ts` — JSON-snapshot repository with a fail-loudly guard if the snapshot is missing/empty.
- `src/features/projects/projectStorage.ts` — localStorage persistence (five functions) and schema versioning; replace with a server-backed module for sync/accounts.
- `db/seed/species.json` + `db/seed.mjs` — the editable species source of truth and its validation pipeline; how to add species.
- `src/data/vocabulary.json` — canonical catalog vocabulary; build scripts and the TS literals in `src/core/domain/plant.ts` must stay in sync (a drift test enforces it).
- `src/features/ai/designAdvisor.ts` — `DesignAdvisor` interface + rule-based implementation; the seam for real AI.

## Core concepts

- **Feet-based world coordinates**: placements store `centerXFeet`/`centerYFeet` (world units), never pixels. Pixels appear only at render time via `pixelsPerFoot(scene)`. Recalibrating the scale rescales every placement automatically, and world units keep GIS/CAD interchange (GeoJSON/DXF) possible.
- **Snapshot undo/redo**: history is full `DesignScene` snapshots. `beginChange()` snapshots before a mutation; drag gestures snapshot once and then mutate with `transient: true`, so an entire drag collapses to one undo step.
- **Repository seam**: all catalog access goes through `PlantRepository`; only `usePlantCatalog` binds the JSON implementation, so swapping in an API/mobile SQLite backend touches no feature code.
- **Self-contained projects**: the property photo is embedded as a data URL inside a versioned JSON document in localStorage; corrupt or newer-schema docs are skipped rather than thrown.
- **Generated vs. hand-authored**: `db/seed/species.json` is written by hand; `src/data/generated/plants.json` and `public/plants/*.svg` are build artifacts of `npm run data` and must never be edited directly.

## Common gotchas

- **Never hand-edit generated files.** Edit `db/seed/species.json`, then run `npm run data`. Real photography: place `<id>-{juvenile|mature}.png` and flip `SEED_IMAGE_EXTENSION` in `db/seed.mjs` to `.png`.
- **Keep `core/` React-free** — no React/MUI imports, no `@features` imports. TypeScript won't enforce it, so it's a discipline that protects the mobile/monorepo seam.
- **Vitest transpiles, it does not type-check.** A green `npm run test` can still hide type errors; `npm run build` (`tsc -b`) is the real gate. Run all of `test && lint && build` before a handoff. (Adding a species changes the "20 species" assumptions in the repository test — regenerate data first, `npm run data`.)
